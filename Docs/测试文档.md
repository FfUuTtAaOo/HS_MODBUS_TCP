## 二、Modbus TCP 协议

### 2.1 协议概述

| 项目 | 值 |
|:---|:---|
| 传输层 | TCP, 端口 502 |
| 帧格式 | MBAP (7 bytes) + PDU |
| 支持功能码 | 0x03 (Read Holding), 0x06 (Write Single), 0x10 (Write Multiple) |
| 数据字节序 | 寄存器值: 大端 (网络序); float32: 2 个寄存器, **小端** (LE) |

> **注意**: 寄存器内部 16-bit 值采用 **大端** (MBAP 标准)。但 float32 的两个寄存器排列采用 **小端**：
> 低地址寄存器 = float 的低 16 位，高地址寄存器 = float 的高 16 位。

### 2.2 MBAP 头结构

| 偏移 | 字节数 | 字段 | 说明 |
|:---|:---|:---|:---|
| 0 | 2 | Transaction ID | 请求/响应匹配，自由填写 |
| 2 | 2 | Protocol ID | 固定 0x0000 |
| 4 | 2 | Length | 后续字节数 (UID + PDU) |
| 6 | 1 | Unit ID | 固定 0x01 |

### 2.3 寄存器地址表

> 地址完全对齐 `modbus-tcp-protocol-v2.0` (已发给客户)
> 写触发寄存器不关心写入的具体值，读始终返回 `0x0000`

#### 2.3.1 系统信息 (只读)

| 地址 | 名称 | 字长 | 类型 | 说明 |
|:---|:---|:---|:---|:---|
| 0x0005~0x000C | SN | 8 | ASCII | 序列号 (16 字符) |
| 0x000D | FW_MAJOR | 1 | uint16 | 主版本号, 例 0x0002 = v2.x |
| 0x000E | FW_MINOR | 1 | uint16 | 次版本号, 例 0x0001 = v2.1 |

#### 2.3.2 控制状态 (读/写)

| 地址 | 名称 | 类型 | 说明 |
|:---|:---|:---|:---|
| 0x0001 | STOP | W | 写触发 (不关心值) → 停止发送 |
| 0x0002 | START | W | 写触发 (不关心值) → 开始连续发送 |
| 0x0003 | SINGLE | W | 写触发 (不关心值) → 单次转换 |
| 0x000F | STATUS | uint16 | BIT0=自启动, BIT1=运行中 (只读) |
| 0x0010 | COMM_ERR | uint16 | RS485 通信错误计数 (只读) |
| 0x0032 | DATA_FORMAT | uint16 | 0=mV, 1=kg, 2=N |
| 0x0200 | FREQ_MODE | uint16 | 0=500Hz, 1=1000Hz (内部扩展) |

#### 2.3.3 力/力矩数据 (只读, float32 LE ×2)

| 地址 | 名称 | 说明 |
|:---|:---|:---|
| 0x0033~0x0034 | FORCE_FX | Fx (N 或 kg 或 mV) |
| 0x0035~0x0036 | FORCE_FY | Fy |
| 0x0037~0x0038 | FORCE_FZ | Fz |
| 0x0039~0x003A | TORQUE_MX | Mx (Nm) |
| 0x003B~0x003C | TORQUE_MY | My |
| 0x003D~0x003E | TORQUE_MZ | Mz |

#### 2.3.4 零点偏移 (读/写, float32 LE ×2)

| 地址 | 名称 |
|:---|:---|
| 0x0050~0x0051 | ZERO_FX |
| 0x0052~0x0053 | ZERO_FY |
| 0x0054~0x0055 | ZERO_FZ |
| 0x0056~0x0057 | ZERO_MX |
| 0x0058~0x0059 | ZERO_MY |
| 0x005A~0x005B | ZERO_MZ |

#### 2.3.5 过载阈值 (读/写, float32 LE ×2)

| 地址 | 名称 |
|:---|:---|
| 0x0070~0x0071 | OVL_FX |
| 0x0072~0x0073 | OVL_FY |
| 0x0074~0x0075 | OVL_FZ |
| 0x0076~0x0077 | OVL_MX |
| 0x0078~0x0079 | OVL_MY |
| 0x007A~0x007B | OVL_MZ |

#### 2.3.6 量程范围 (读/写, float32 LE ×2)

| 地址 | 名称 | 说明 |
|:---|:---|:---|
| 0x007C~0x007D | RANGE_FX_MIN | Fx 量程最小值 |
| 0x007E~0x007F | RANGE_FX_MAX | Fx 量程最大值 |
| 0x0080~0x0081 | RANGE_FY_MIN | Fy 量程最小值 |
| 0x0082~0x0083 | RANGE_FY_MAX | Fy 量程最大值 |
| 0x0084~0x0085 | RANGE_FZ_MIN | Fz 量程最小值 |
| 0x0086~0x0087 | RANGE_FZ_MAX | Fz 量程最大值 |
| 0x0088~0x0089 | RANGE_MX_MIN | Mx 量程最小值 |
| 0x008A~0x008B | RANGE_MX_MAX | Mx 量程最大值 |
| 0x008C~0x008D | RANGE_MY_MIN | My 量程最小值 |
| 0x008E~0x008F | RANGE_MY_MAX | My 量程最大值 |
| 0x0090~0x0091 | RANGE_MZ_MIN | Mz 量程最小值 |
| 0x0092~0x0093 | RANGE_MZ_MAX | Mz 量程最大值 |

#### 2.3.7 网络配置 (读/单写)

| 地址 | 名称 | 字长 | 说明 |
|:---|:---|:---|:---|
| 0x0100~0x0102 | MAC | 3 | 6 字节 MAC (后 3 寄存器填充 0) |
| 0x0106~0x0107 | IP | 2 | 4 字节 IP, 例 192.168.1.200 = 0xC0A8_01C8 |
| 0x0108~0x0109 | SUBNET | 2 | 4 字节子网掩码 |
| 0x010A~0x010B | GATEWAY | 2 | 4 字节网关 |

#### 2.3.8 自检状态 (只读, 内部调试用, 不在客户协议中)

| 地址 | 名称 | 字长 | 说明 |
|:---|:---|:---|:---|
| 0x0210~0x0211 | ST_ERROR | 2 | 错误标志 (uint32 LE) |
| 0x0212 | ST_ADC_ID | 1 | [ADC_ID, ERR_REG] |
| 0x0213 | ST_W5500 | 1 | [VER, LINK+SOCKETS] |
| 0x0214 | ST_RS485 | 1 | [USART_OK, DMA_OK] |
| 0x0215 | ST_FLASH | 1 | [VALID, MATRIX_OK, ZERO_OK, CFG_OK] |

#### 2.3.9 校准触发 (只写, 触发动作)

| 地址 | 说明 |
|:---|:---|
| 0x0030 | ZERO — 启动零点校准 (写任意值触发) |
| 0x0031 | UNZERO — 取消零点校准 (写任意值触发) |

#### 2.3.8 异常码

| 码 | 名称 | 含义 |
|:---|:---|:---|
| 0x01 | ILLEGAL_FC | 不支持的功能码 |
| 0x02 | ILLEGAL_ADDR | 寄存器地址无效 |
| 0x03 | ILLEGAL_DATA | 数据值无效或长度不匹配 |
| 0x04 | ILLEGAL_ACTION | 操作不允许 (如写只读寄存器) |

### 2.4 指令与响应示例

#### 示例 1: 读取力/力矩数据 (0x03)

**功能**: 读取 Fx, Fy, Fz, Mx, My, Mz (12 个寄存器, 地址 0x0033~0x003E)

```
请求 (TCP payload, HEX):
┌──────────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┐
│ 00 01    │ 00 00 │ 00 06│ 01   │ 03   │ 00 33│ 00 0C│                                 │
├──────────┼──────┼──────┼──────┼──────┼──────┼──────┤                                 │
│ TID=1    │ PID=0 │ Len=6│ UID=1│ FC=03│ 起始  │ 数量  │                                 │
│          │       │      │      │      │ 0x0033│ 12   │                                 │
└──────────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘

响应 (TCP payload, HEX):
┌──────────┬──────┬──────┬──────┬──────┬──────┬───────────────────────────────────────┐
│ 00 01    │ 00 00 │ 00 1B│ 01   │ 03   │ 18   │ 24 字节数据 (12 寄存器 × 2)              │
├──────────┼──────┼──────┼──────┼──────┼──────┼───────────────────────────────────────┤
│ TID=1    │ PID=0 │ Len= │ UID=1│ FC=03│ 字节  │                                       │
│          │       │ 27   │      │      │ 数=24│                                       │
└──────────┴──────┴──────┴──────┴──────┴──────┴───────────────────────────────────────┘

数据段解析 (24 字节, 每 4 字节一个 float32 LE):
  字节 0-3:  Fx = 0x0000803F → 小端 uint32=0x3F800000 → float=1.0
  字节 4-7:  Fy = 0x00000040 → 小端 uint32=0x40000000 → float=2.0
  字节 8-11: Fz = 0x00004040 → 小端 uint32=0x40400000 → float=3.0
  字节 12-15: Mx = 0x0000803F → float=1.0
  字节 16-19: My = 0x00000040 → float=2.0
  字节 20-23: Mz = 0x00004040 → float=3.0

解释:
  - Fx=1.0 N, Fy=2.0 N, Fz=3.0 N
  - Mx=1.0 Nm, My=2.0 Nm, Mz=3.0 Nm
  - 实际输出取决于当前数据格式设置 (mV/kg/N)
```

  ─────  ─────  ─────  ──  ──  ─────  ─────

#### 示例 5: 写命令寄存器 — 开始连续发送 (0x06)

**功能**: 写 STOP (0x0001) — 写触发寄存器, 不关心写入值

```
请求:
  00 05  00 00  00 06  01  06  00 01  00 00
  ─────  ─────  ─────  ──  ──  ─────  ─────
  TID=5  PID=0  Len=6  UID FC  地址    值(任意)
                         =1 =06  0x0001  → STOP

响应 (echo):
  00 05  00 00  00 06  01  06  00 01  00 00

解释:
  - 传感器停止通过 RS485 连续发送力数据
  - Modbus TCP 侧不受影响, 仍可通过 0x0033 读取最新数据
  - 写 0x0002 = START, 写 0x0003 = SINGLE
  - 读取 0x0001~0x0003 始终返回 0x0000 (auto-reset)
```

#### 示例 6: 异常响应 — 无效地址 (0x02)

**功能**: 尝试读取 gap 地址 0x0004 (不在任何 valid_range 块内)

```
请求:
  00 06  00 00  00 06  01  03  00 04  00 01
  ─────  ─────  ─────  ──  ──  ─────  ─────
  TID=6  PID=0  Len=6  UID FC  地址    1 个
                         =1 =03  0x0004  (gap 地址)

响应 (异常帧):
  00 06  00 00  00 03  01  83  02
  ─────  ─────  ─────  ──  ──  ──
  TID=6  PID=0  Len=3  UID 83= 异常码
                         =1  FC|0x80  =0x02

解释:
  - FC 最高位置 1: 0x03 → 0x83 表示异常
  - 异常码 0x02 = ILLEGAL_ADDR (地址无效)
  - PDU 长度 = 3 (UID + FC + 异常码)
  - 0x0004 在触发块(0x0003)和系统信息块(0x0005)之间，属于未映射区域
```

## 三、RS485 串口协议

### 3.1 协议概述

| 项目 | 值 |
|:---|:---|
| 物理层 | USART2, 460800 bps, 8N1 |
| 帧格式 | `AA 55 [CMD] [PAYLOAD] 0D 0A` |
| 字节序 | 多字节数值一律 **小端** (LE) |
| 接收方式 | DMA + UART IDLE 中断 |
| 最大帧长 | 255 字节 (含帧头帧尾) |

### 3.2 帧结构

```
┌─────┬─────┬─────┬──────────────┬─────┬─────┐
│ AA  │ 55  │ CMD │  PAYLOAD...  │ 0D  │ 0A  │
├─────┼─────┼─────┼──────────────┼─────┼─────┤
│ SOF │ SOF │ 命令 │  数据载荷     │ EOF │ EOF │
│  HI │  LO │      │  (可变长度)   │  HI │  LO │
└─────┴─────┴─────┴──────────────┴─────┴─────┘
```

**响应帧**: 命令字节最高位置 1  
`AA 55 [CMD | 0x80] [PAYLOAD] 0D 0A`

### 3.3 命令表

| CMD | 名称 | 方向 | 载荷长度 | 说明 |
|:---|:---|:---|:---|:---|
| 0x01 | STOP | → | 0 | 停止连续发送 |
| 0x02 | START | → | 0 | 开始连续发送 |
| 0x03 | SINGLE | → | 0 | 单次请求, 返回一帧数据 |
| 0x04 | SET_FREQ | → | 1 | 设置频率: 0=500Hz, 1=1000Hz |
| 0x05 | QUERY_SN | → | 0 | 查询序列号 |
| 0x06 | QUERY_VER | → | 0 | 查询固件版本 |
| 0x07 | QUERY_STATUS | → | 0 | 查询系统状态 |
| 0x08 | ZERO | → | 0 | 零点校准 (20 点平均) |
| 0x09 | UNZERO | → | 0 | 取消零点 (恢复原始偏移) |
| 0x0A | SET_FORMAT | → | 1 | 设置格式: 0=mV, 1=kg, 2=N |
| 0x0B | SET_IP | → | 4 | 设置 IP (4 字节 LE) |
| 0x0C | SET_MAC | → | 6 | 设置 MAC (6 字节) |
| 0x0D | SET_SUBNET | → | 4 | 设置子网掩码 (4 字节 LE) |
| 0x0E | SET_GW | → | 4 | 设置网关 (4 字节 LE) |
| 0x0F | QUERY_NET | → | 0 | 查询网络配置 |
| 0x20 | SET_MATRIX | → | 144 | 上传解耦矩阵 (6×6 float32 LE) |
| 0x35 | DEBUG_MODE | → | 0 | 切换调试模式 |

### 3.4 连续数据帧

传感器在 START 模式下自动发送, 帧格式:

```
AA 55 00 [SEQ(4B LE)] [Fx(4B LE)] [Fy(4B LE)] [Fz(4B LE)] [Mx(4B LE)] [My(4B LE)] [Mz(4B LE)] 0D 0A
└─SOF─┘ └CMD=0x00──┘ └───序列号──┘ └──────────────6×float32 LE (24 字节)──────────────┘ └─EOF─┘
```

总帧长: 2 + 1 + 4 + 24 + 2 = **33 字节**

### 3.5 指令与响应示例

#### 示例 R1: 停止连续发送 (0x01)

```
发送:  AA 55 01 0D 0A
       └SOF─┘└CMD┘└EOF─┘
       载荷长度=0

响应:  AA 55 81 0D 0A
       └SOF─┘└81=0x01|0x80┘└EOF─┘

解释:
  - 0x01 → STOP 命令
  - 0x81 → 响应 (0x01 | 0x80), 无附加数据
  - 传感器停止通过 RS485 自动发送连续数据帧
```

---

#### 示例 R2: 开始连续发送 (0x02)

```
发送:  AA 55 02 0D 0A

响应:  AA 55 82 0D 0A

解释:
  - 传感器开始以当前频率 (500Hz/1000Hz) 连续发送数据帧
  - 每帧格式见 §3.4 连续数据帧
```

#### 示例 R3: 单次请求数据 (0x03)

```
发送:  AA 55 03 0D 0A

响应 (连续数据帧, CMD=0x00, 共 33 字节):
  AA 55 00 01 00 00 00  00 00 80 3F 00 00 00 40 00 00 40 40  00 00 80 3F 00 00 00 40 00 00 40 40  0D 0A
  └SOF─┘ └─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘ └EOF─┘
          SEQ=1 (LE)       Fx=1.0          Fy=2.0          Fz=3.0          Mx=1.0          My=2.0          Mz=3.0
                         (0x3F800000)     (0x40000000)    (0x40400000)    (0x3F800000)    (0x40000000)    (0x40400000)

解释:
  - CMD=0x00 表示这是数据帧 (不是命令响应)
  - SEQ=0x00000001: 帧序号 (每次请求递增)
  - 6 个 float32 小端: Fx=1.0, Fy=2.0, Fz=3.0, Mx=1.0, My=2.0, Mz=3.0
  - 单位取决于当前 DATA_FORMAT 设置 (mV/kg/N)
```

## 四、错误处理

### 4.1 Modbus TCP 异常

| 异常码 | 场景 | 响应格式 |
|:---|:---|:---|
| 0x01 | 使用 0x03/0x06/0x10 以外的功能码 | FC\|0x80 + 0x01 |
| 0x02 | 寄存器地址无效 / 写只读寄存器 (如 0x0033) | FC\|0x80 + 0x02 |
| 0x03 | PDU 长度不匹配 / 字节数 != 寄存器数×2 / count=0或>125 | FC\|0x80 + 0x03 |
| 0x04 | 操作不允许 (预留，当前代码未使用) | FC\|0x80 + 0x04 |

### 4.2 RS485 错误处理

- **帧格式错误**: 非 `AA 55...0D 0A` 的帧被静默丢弃
- **载荷长度不足**: 命令要求的载荷不够 → `comm_error_cnt++`, 不执行
- **无效参数**: 如 SET_FORMAT 值 >2 → `comm_error_cnt++`, 不切换
- **未知命令**: `comm_error_cnt++`, 静默忽略

### 4.3 通信错误计数

- 通过 Modbus 寄存器 `0x0010` (COMM_ERR) 或 RS485 命令 `0x07` (QUERY_STATUS) 查询
- 仅计数 RS485 侧错误, 不清零 (上电复位后归零)

## 五、常见问题

### Q1: Modbus 读取力数据返回全 0?

**可能原因**:  
- 传感器未启动连续采集 (需写 START 触发寄存器 `0x0002`)  
- 数据格式设置为 mV 但 ADC 未完成校准, 原始值接近 0  

**排查**: 读取 STATUS (0x000F), BIT1 应为 1 表示运行中。

### Q2: RS485 发送命令无响应?

**可能原因**:  
- 波特率不匹配 (必须 460800)  
- 帧格式错误 (缺少 AA 55 头或 0D 0A 尾)  
- 硬件接线错误 (TX/RX 交叉, GND 未接)  

**排查**: 用示波器或逻辑分析仪检查 USART2 TX 引脚是否有输出。

### Q3: 自检报告 SPI Communication FAIL?

**可能原因**:  
- SPI2 引脚配置错误  
- LHA7668 / W5500 硬件故障或焊接问题  
- 电源不稳定  

**排查**: 检查 SPI2 SCK/MOSI/MISO 波形, 确认 CS 引脚电平正确。

### Q4: Flash 自检 FAIL 且显示 "EMPTY"?

**正常现象**: 首次上电 Flash 未写入过数据, magic 校验失败。  
**解决**: 通过 RS485 上传一次解耦矩阵 (0x20) 并执行零点校准 (0x08), 之后 Flash 状态会变为 VALID。
