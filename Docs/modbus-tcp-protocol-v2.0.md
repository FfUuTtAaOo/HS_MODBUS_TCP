## 1 概述

本文档定义了中科米点六维力传感器基于 Modbus-TCP 协议的上位机通信规范。传感器作为 Modbus TCP Server，默认监听端口 **502**，支持多客户端并发连接。

### 协议范围说明

Modbus-TCP 通道负责以下功能：

- 控制指令（停止发送、开始转换、单次触发）
- 传感器清零与零点偏移管理
- 设备信息查询（序列号、固件版本）
- 状态监控（系统状态、通信错误计数、过载保护）
- 数据输出（矩阵滤波数据 kg/N、原始数据 mV）
- 网络参数配置（IP、子网掩码、网关等）

### 1.1 数据类型与字节序

六维力传感器同时测量三个方向的力（Fx, Fy, Fz，单位 N）和三个方向的力矩（Mx, My, Mz，单位 N·m）。

| 数据类型      | 占用寄存器     | 字节序                | 示例                       |
|:--------- |:--------- |:------------------ |:------------------------ |
| uint16    | 1 个寄存器    | 大端 (Big-Endian)    | `0x0001` = 1             |
| float32   | 2 个寄存器    | 小端 (Little-Endian) | 1.0 = `[0x3F80, 0x0000]` |
| ASCII 字符串 | 每寄存器 2 字符 | 顺序存放               | `"AB"` = `[0x4142]`      |

## 2 Modbus-TCP 帧格式

Modbus-TCP 在标准 Modbus RTU 帧前增加 7 字节 MBAP 头，去除 CRC 校验（由 TCP 层保证数据完整性）：

| 偏移  | 字段                     | 长度   | 说明                                 |
|:--- |:---------------------- |:---- |:---------------------------------- |
| 0   | 事务标识符 (Transaction ID) | 2 字节 | 主站生成，从站原样返回，用于匹配请求/响应              |
| 2   | 协议标识符 (Protocol ID)    | 2 字节 | 固定为 `0x0000`（Modbus 协议）            |
| 4   | 长度 (Length)            | 2 字节 | 后续字节数（单元标识 + 功能码 + 数据）             |
| 6   | 单元标识 (Unit ID)         | 1 字节 | 固定为 `0x01`（传感器设备标识）                |
| 7   | 功能码                    | 1 字节 | 同 Modbus RTU（0x03 / 0x06 / 0x10 等） |
| 8+  | 数据                     | 变长   | 与 Modbus RTU 相同                    |

**示例 — 读保持寄存器 (功能码 0x03，读 1 个寄存器)：**

```
Modbus RTU:            01 03 00 01 00 01 D5 CA
Modbus-TCP MBAP + RTU: 00 01 00 00 00 06 01 03 00 01 00 01
                       |--事务ID--| |协议| |-长度-| |U| |FC| |-地址-| |-数量-|
```

**关键区别：**

- TCP 帧无 CRC，由 TCP/IP 层保证完整性
- 增加事务 ID 支持并发请求/响应匹配
- 单元标识固定 0x01（单设备时无实际路由作用）

## 3 寄存器定义

寄存器按功能分为五大类。所有寄存器均通过 Modbus 功能码访问：

| 功能码    | 用途     |
|:------ |:------ |
| `0x03` | 读保持寄存器 |
| `0x06` | 写单个寄存器 |
| `0x10` | 写多个寄存器 |

---

### 3.1 控制指令

控制指令寄存器采用**写触发**机制：传感器检测到 Modbus 写操作事件（功能码 0x06）即执行对应动作，不关心写入的具体值。触发后寄存器自动归零。

> **上位机约定**：每次写入 `0x0001` 作为标准触发值。

| 地址       | 名称     | 说明           | 默认值      | 读写  | 触发机制          |
|:-------- |:------ |:------------ |:-------- |:--- |:------------- |
| `0x0001` | 停止发送   | 写任意值停止数据主动发送 | `0x0000` | W   | 写事件触发，触发后自动归零 |
| `0x0002` | 开始数据转换 | 写任意值启动连续数据转换 | `0x0000` | W   | 写事件触发，触发后自动归零 |
| `0x0003` | 单次转换   | 触发单次转换       | —        | W   | 写事件触发         |

#### 3.1.1 停止发送 (0x0001)

停止传感器主动数据发送。写入后传感器立即停止连续数据输出，回到静默状态。

| 属性    | 值                                |
|:----- |:-------------------------------- |
| 寄存器地址 | `0x0001`                         |
| 访问类型  | 只写 (W)                           |
| 触发机制  | 写事件触发（检测功能码 0x06）                |
| 触发后行为 | 停止数据发送，寄存器值自动恢复为 `0x0000`        |
| 上位机约定 | 每次写入 `0x0001`                    |
| 重试说明  | 通信超时重发会重复触发，无副作用（已停止状态下再次停止仍为停止） |

**通信示例：**

```
请求: 00 02 00 00 00 06 01 06 00 01 00 01
      |--TID--| |-PID-| |-LEN-| |U| |FC| |ADDR| |-VAL-|
响应: 00 02 00 00 00 06 01 06 00 01 00 01  (原样返回)
```

#### 3.1.2 开始数据转换 (0x0002)

启动传感器连续数据转换和主动发送。写入后传感器开始按设定频率持续推送六维力数据。数据格式由 `0x0032` 决定，默认上电为 N 格式。数据内容已扣除零点偏移（mV 格式除外）。

| 属性    | 值                            |
|:----- |:---------------------------- |
| 寄存器地址 | `0x0002`                     |
| 访问类型  | 只写 (W)                       |
| 触发机制  | 写事件触发（检测功能码 0x06）            |
| 触发后行为 | 启动连续转换和发送，寄存器值自动恢复为 `0x0000` |
| 上位机约定 | 每次写入 `0x0001`                |

**通信示例（触发指令）：**

```
请求: 00 03 00 00 00 06 01 06 00 02 00 01
响应: 00 03 00 00 00 06 01 06 00 02 00 01  (原样返回，触发成功)
```

**触发后，传感器持续推送的数据帧格式（等同于不断返回 0x0033 的读结果）：**

```
|-- MBAP Header --|  |-- 读响应 --|  |------- 6 通道 float32 LE (N / N·m) ----------|

00 XX 00 00 00 1B  01 03 18  Fx_H Fx_L Fy_H Fy_L Fz_H Fz_L  Mx_H Mx_L My_H My_L Mz_H Mz_L
```

| 段        | 值       | 说明                                       |
|:-------- |:------- |:---------------------------------------- |
| TID      | `00 XX` | 帧序号，每帧递增                                 |
| PID      | `00 00` | 协议标识，固定 0x0000                           |
| LEN      | `00 1B` | 长度 = 27 (UID + FC + 24 数据)               |
| UID      | `01`    | 单元标识                                     |
| FC       | `03`    | 功能码（读保持寄存器响应）                            |
| BYTE_CNT | `18`    | 数据字节数 = 24                               |
| Fx~Mz    | 24 字节   | 6 个 float32 LE，单位由 0x0032 决定。**已扣除零点偏移（mV 格式除外）。** |

**停止连续发送：** 写 `0x0001`（停止发送），传感器立即停止数据推送。

#### 3.1.3 单次转换 (0x0003)

触发一次六维力数据采集与转换，转换结果存入数据寄存器 `0x0033~0x003E`，上位机随后通过读该寄存器组获取单次采样值。输出单位由 `0x0032` 决定。

| 属性    | 值        |
|:----- |:-------- |
| 寄存器地址 | `0x0003` |
| 访问类型  | 只写 (W)   |
| 触发机制  | 写事件触发    |

**使用流程：**

1. 可选：写 `0x0032` 切换所需单位（默认 N）
2. 写 `0x0003` 触发转换
3. 延时 >= 2ms
4. 读 `0x0033~0x003E`（12 个寄存器）获取结果

**完整通信示例（触发 + 读取数据）：**

```
--- Step 1: 触发单次转换 ---
请求: 00 04 00 00 00 06 01 06 00 03 00 01
响应: 00 04 00 00 00 06 01 06 00 03 00 01  (原样返回，触发成功)

--- 延时 >= 2ms ---

--- Step 2: 读 0x0033（数据寄存器，12 个寄存器）---
请求: 00 05 00 00 00 06 01 03 00 33 00 0C
      |--TID--| |-PID-| |-LEN-| |U| |FC| |ADDR| |CNT=12|

响应: 00 05 00 00 00 1B 01 03 18
      [Fx_H Fx_L] [Fy_H Fy_L] [Fz_H Fz_L]
      [Mx_H Mx_L] [My_H My_L] [Mz_H Mz_L]
      (24 字节 = 6×float32 LE，单位由 0x0032 决定)
```

| 段        | 值       | 说明                          |
|:-------- |:------- |:--------------------------- |
| TID      | `00 05` | 与请求一致                       |
| LEN      | `00 1B` | 长度 = 27                     |
| BYTE_CNT | `18`    | 数据字节数 = 24                  |
| Fx~Mz    | 24 字节   | 6 × float32 LE，单位由 0x0032 决定 |

### 3.2 传感器清零与零点偏移

#### 输出值计算公式

```
F_out[i] = F_raw[i] - F_zero[i]    (i = Fx, Fy, Fz, Mx, My, Mz)
```

- `F_raw`：传感器原始采集值（经矩阵解耦后）
- `F_zero`：存储的零点偏移值，可读可写
- `F_out`：输出给上位机的最终值（数据寄存器 0x0033~0x003E 中返回的值）

> **关键理解**：当 `F_zero` 全部为 0 时，`F_out = F_raw`，输出值 = 原始值，即"未去皮"状态。

#### 3.2.1 自动清零 — 触发寄存器 (0x0030)

触发自动清零后，传感器采集当前 6 个通道的实时值，将其自动存入零点偏移寄存器（0x0050~0x005B），后续输出值将减去此零点偏移。

| 属性    | 值                                                           |
|:----- |:----------------------------------------------------------- |
| 寄存器地址 | `0x0030`                                                    |
| 访问类型  | 只写 (W)                                                      |
| 触发机制  | 写事件触发（检测功能码 0x06）                                           |
| 触发后行为 | 采集当前 6 通道值 → 自动写入 0x0050~0x005B → 寄存器 0x0030 自动恢复为 `0x0000` |
| 清零后确认 | 建议读 0x0050~0x005B（12 个寄存器）验证零点偏移是否正确写入                      |

> **注意**：清零前请确保传感器处于零负载状态，否则会产生固定偏置误差。

**通信示例（触发清零）：**

```
请求: 00 10 00 00 00 06 01 06 00 30 00 01
      |--TID--| |-PID-| |-LEN-| |U| |FC| |ADDR| |-触发器-|
响应: 00 10 00 00 00 06 01 06 00 30 00 01
```

#### 3.2.2 零点偏移寄存器 (0x0050~0x005B)

存储 6 维零点偏移值，可读可写。自动清零时由传感器自动填充，也可手动写入以恢复之前保存的参数或加载外部标定值。

| 通道  | 寄存器地址           | 数据类型       | 说明               |
|:--- |:--------------- |:---------- |:---------------- |
| Fx  | `0x0050~0x0051` | float32 LE | Fx 零点力偏移，单位 N    |
| Fy  | `0x0052~0x0053` | float32 LE | Fy 零点力偏移，单位 N    |
| Fz  | `0x0054~0x0055` | float32 LE | Fz 零点力偏移，单位 N    |
| Mx  | `0x0056~0x0057` | float32 LE | Mx 零点力矩偏移，单位 N·m |
| My  | `0x0058~0x0059` | float32 LE | My 零点力矩偏移，单位 N·m |
| Mz  | `0x005A~0x005B` | float32 LE | Mz 零点力矩偏移，单位 N·m |

**通信示例（手动设置零点偏移，如恢复之前保存的值）：**

```
请求: 00 20 00 00 00 1B 01 10 00 50 00 0C 18 [24字节 = 6×float32 LE]
响应: 00 20 00 00 00 06 01 10 00 50 00 0C
```

#### 3.2.3 取消清零 — 触发寄存器 (0x0031)

触发后，传感器将 0x0050~0x005B 全部置为 `0.0`（6 个 float32 零值），此时 `F_zero[i] = 0`，输出值 = 原始采集值，即恢复绝对零点（取消去皮）。

| 属性    | 值                                                |
|:----- |:------------------------------------------------ |
| 寄存器地址 | `0x0031`                                         |
| 访问类型  | 只写 (W)                                           |
| 触发机制  | 写事件触发（检测功能码 0x06）                                |
| 触发后行为 | 将 0x0050~0x005B 全部置零 → 寄存器 0x0031 自动恢复为 `0x0000` |

**通信示例（取消清零）：**

```
请求: 00 11 00 00 00 06 01 06 00 31 00 01
      |--TID--| |-PID-| |-LEN-| |U| |FC| |ADDR| |-触发器-|
响应: 00 11 00 00 00 06 01 06 00 31 00 01
```

### 3.3 设备信息

| 地址              | 名称   | 说明                  | 默认值 | 读写  |
|:--------------- |:---- |:------------------- |:--- |:--- |
| `0x0005~0x000C` | 序列号  | 8 个寄存器，ASCII 序列号，只读 | —   | R   |
| `0x000D~0x000E` | 固件版本 | 2 个寄存器，版本信息，只读      | —   | R   |

#### 3.3.1 序列号 (0x0005)

读取传感器出厂序列号（ASCII 字符串，最多 16 字符）。占用 8 个连续寄存器（0x0005~0x000C），每个寄存器存放 2 个 ASCII 字符。

**通信示例：**

```
请求: 00 05 00 00 00 06 01 03 00 05 00 08
响应: 00 05 00 00 00 13 01 03 10 4D 44 30 30 30 31 32 33 34 35 36 37 38 00 00 00
      → 序列号: "MD00012345678"
```

#### 3.3.2 固件版本 (0x000D)

读取固件版本号，占用 2 个寄存器。高寄存器为主版本号，低寄存器为次版本号。

**通信示例：**

```
请求: 00 06 00 00 00 06 01 03 00 0D 00 02
响应: 00 06 00 00 00 07 01 03 04 00 02 00 01
      → 版本: v2.1
```

### 3.4 状态监控与保护

| 地址              | 名称     | 说明                                    | 默认值      | 读写  |
|:--------------- |:------ |:------------------------------------- |:-------- |:--- |
| `0x000F`        | 系统状态   | 见 3.4.1 系统状态位定义                       | `0x0000` | R   |
| `0x0010`        | 通信错误计数 | TCP 通信异常累计次数                          | `0x0000` | R   |
| `0x0070~0x007B` | 过载阈值   | 6 维阈值 (Fx/Fy/Fz/Mx/My/Mz), float32 LE | 见 3.4.3 | R/W |
| `0x007C~0x0093` | 阈值范围   | 6 通道阈值允许范围 (Min/Max), float32 LE   | 见 3.4.4 | R/W |

#### 3.4.1 系统状态 (0x000F)

系统状态寄存器提供传感器实时运行状态，包括硬件自检、通信质量和过载告警。

| 位       | 名称          | 说明                            |
|:------- |:----------- |:----------------------------- |
| bit0    | EEPROM_FAIL   | EEPROM 初始化失败（上电自检，锁存）                       |
| bit1    | ADC_FAIL      | ADC 初始化失败（上电自检，锁存）                          |
| bit2    | CRC_ERR       | 通信校验失败（发生过=1，读后自动清零）                        |
| bit3    | OVERLOAD      | 过载告警（任一通道 >= 对应阈值时置 1，回落自动清零）               |
| bit4    | PARAM_ERR     | 参数写入越界（阈值超出 RangeMin~RangeMax 时置 1，读后自动清零） |
| bit5~15 | —             | 保留                                              |

**通信示例：**

```
请求: 00 07 00 00 00 06 01 03 00 0F 00 01
响应: 00 07 00 00 00 05 01 03 02 00 00  → 无异常
响应: 00 07 00 00 00 05 01 03 02 00 08  → 过载告警
响应: 00 07 00 00 00 05 01 03 02 00 10  → 参数写入越界
```

#### 3.4.2 通信错误计数 (0x0010)

记录上电以来 TCP 通信异常累计次数（如连接超时、帧格式错误等）。只读，掉电清零。

```
请求: 00 08 00 00 00 06 01 03 00 10 00 01
响应: 00 08 00 00 00 05 01 03 02 00 03  → 累计 3 次异常
```

#### 3.4.3 过载阈值 (0x0070~0x007B)

设置六维力/力矩的过载保护阈值。当任一通道采样值 >= 对应阈值时，系统状态寄存器的 OVERLOAD 位置 1。

> **注意**：此阈值仅用于过载告警判断，不触发硬件保护。写入值受阈值范围限制（见 3.4.4），超出范围时写入无效。

| 通道  | 寄存器地址           | 单位  | 默认值    |
|:--- |:--------------- |:--- |:------ |
| Fx  | `0x0070~0x0071` | N   | 2000.0 |
| Fy  | `0x0072~0x0073` | N   | 2000.0 |
| Fz  | `0x0074~0x0075` | N   | 5000.0 |
| Mx  | `0x0076~0x0077` | N·m | 200.0  |
| My  | `0x0078~0x0079` | N·m | 200.0  |
| Mz  | `0x007A~0x007B` | N·m | 200.0  |

每个通道独立设置阈值，写入时使用功能码 0x10 一次写入 2 个寄存器（float32 LE）。

**通信示例（设置 Fx 阈值 = 1000.0 N）：**

```
请求: 00 09 00 00 00 09 01 10 00 70 00 02 04 44 7A 00 00
      |--TID--| |-PID-| |-LEN-| |U| |FC| |ADDR| |CNT| |N| |- 1000.0 LE -|
响应: 00 09 00 00 00 06 01 10 00 70 00 02
```

#### 3.4.4 阈值范围 (0x007C~0x0093)

定义每个通道过载阈值的允许范围（最小值 / 最大值），防止误写入极端值。可读可写，方便适配不同量程的传感器型号。

每个通道占用 4 个寄存器：`RangeMin` + `RangeMax`（各 float32 LE）。

| 通道  | 寄存器地址             | 字段        | 单位  | 默认值     |
|:--- |:----------------- |:--------- |:--- |:------- |
| Fx  | `0x007C~0x007D`   | 阈值最小值     | N   | 0.1     |
|     | `0x007E~0x007F`   | 阈值最大值     | N   | 50000.0 |
| Fy  | `0x0080~0x0081`   | 阈值最小值     | N   | 0.1     |
|     | `0x0082~0x0083`   | 阈值最大值     | N   | 50000.0 |
| Fz  | `0x0084~0x0085`   | 阈值最小值     | N   | 0.1     |
|     | `0x0086~0x0087`   | 阈值最大值     | N   | 100000.0 |
| Mx  | `0x0088~0x0089`   | 阈值最小值     | N·m | 0.01    |
|     | `0x008A~0x008B`   | 阈值最大值     | N·m | 5000.0  |
| My  | `0x008C~0x008D`   | 阈值最小值     | N·m | 0.01    |
|     | `0x008E~0x008F`   | 阈值最大值     | N·m | 5000.0  |
| Mz  | `0x0090~0x0091`   | 阈值最小值     | N·m | 0.01    |
|     | `0x0092~0x0093`   | 阈值最大值     | N·m | 5000.0  |

> **写入校验**：设置过载阈值（0x0070~0x007B）时，传感器检查写入值是否在对应通道的 `[RangeMin, RangeMax]` 区间内。超出范围则写入无效、原阈值保持不变，同时系统状态寄存器（0x000F）的 `PARAM_ERR` 位置 1，上位机可通过读状态寄存器获知写入失败。

**通信示例（读 Fx 阈值范围）：**

```
请求: 00 10 00 00 00 06 01 03 00 7C 00 04
      |--TID--| |-PID-| |-LEN-| |U| |FC| |ADDR| |CNT=4|
响应: 00 10 00 00 00 0B 01 03 08 3D CC CC CD 47 43 50 0D
      → Min = 0.1, Max = 50000.0
```

**通信示例（修改 Fz 阈值最大值为 20000.0）：**

```
请求: 00 11 00 00 00 09 01 10 00 86 00 02 04 46 9C 40 00
      |--TID--| |-PID-| |-LEN-| |U| |FC| |ADDR| |CNT| |N| |- 20000.0 LE -|
响应: 00 11 00 00 00 06 01 10 00 86 00 02
```

### 3.5 数据输出

数据输出采用"格式选择 + 统一数据区"设计：

- **`0x0032`（格式选择）**：写寄存器切换当前输出单位，传感器内部完成单位换算，数据统一映射到 `0x0033~0x003E`
- **`0x0033~0x003E`（数据寄存器）**：只读，始终返回 12 个寄存器（6 通道 × 2 寄存器 / float32 LE），内容由 `0x0032` 决定

> 默认上电格式为 N（`0x0032 = 2`）。kg 和 N 的输出值已扣除零点偏移：`F_out[i] = F_raw[i] - F_zero[i]`。mV 为原始电压值，不扣除零点偏移。

#### 3.5.1 输出格式选择 (0x0032)

写入指定值切换数据输出单位。该寄存器**可读可写**，读取可获知当前格式。

| 写入值  | 格式          | 说明                                     |
|:---- |:----------- |:-------------------------------------- |
| `0`  | 原始数据 (mV)   | 数据寄存器返回原始电压值 mV，未经矩阵解耦，不扣除零点偏移        |
| `1`  | 矩阵滤波数据 (kg) | 数据寄存器返回矩阵解耦滤波后的值，力: kg, 力矩: kg·m，已扣除零点偏移 |
| `2`  | 矩阵滤波数据 (N)  | 数据寄存器返回矩阵解耦滤波后的值，力: N, 力矩: N·m，已扣除零点偏移  |

**通信示例（切换为 N 格式）：**

```
请求: 00 0A 00 00 00 06 01 06 00 32 00 02
      |--TID--| |-PID-| |-LEN-| |U| |FC| |ADDR| |VAL=2|
响应: 00 0A 00 00 00 06 01 06 00 32 00 02
```

**读取当前格式：**

```
请求: 00 0B 00 00 00 06 01 03 00 32 00 01
响应: 00 0B 00 00 00 05 01 03 02 00 02  → 当前格式 = N
```

#### 3.5.2 数据寄存器 (0x0033~0x003E)

只读，始终返回 6 维力数据（12 个寄存器 = 6 × float32 LE）。实际输出的物理单位由 `0x0032` 决定。

| 通道 | 寄存器地址           | 数据类型       | 说明                           |
|:--- |:--------------- |:---------- |:---------------------------- |
| Fx  | `0x0033~0x0034` | float32 LE | Fx 力，单位由 0x0032 决定            |
| Fy  | `0x0035~0x0036` | float32 LE | Fy 力，单位由 0x0032 决定            |
| Fz  | `0x0037~0x0038` | float32 LE | Fz 力，单位由 0x0032 决定            |
| Mx  | `0x0039~0x003A` | float32 LE | Mx 力矩，单位由 0x0032 决定           |
| My  | `0x003B~0x003C` | float32 LE | My 力矩，单位由 0x0032 决定           |
| Mz  | `0x003D~0x003E` | float32 LE | Mz 力矩，单位由 0x0032 决定           |

**通信示例（当前格式 = N，读数据）：**

```
请求: 00 0C 00 00 00 06 01 03 00 33 00 0C
响应: 00 0C 00 00 00 1B 01 03 18
      Fx_hi Fx_lo Fy_hi Fy_lo Fz_hi Fz_lo
      Mx_hi Mx_lo My_hi My_lo Mz_hi Mz_lo
      (24 字节 = 6 float32 LE, 单位由 0x0032 决定)
```

**三种格式的数据关系：**

```
原始 mV → 经标定矩阵解耦 → 滤波 → N 数据 (已扣零点偏移)
N 数据 ÷ 9.80665 → kg 数据 (已扣零点偏移)
```

> - 零点偏移值可从 0x0050~0x005B 读取

### 3.6 网络参数

网络参数寄存器用于配置传感器以太网接口（W5500），修改后需重启生效。

| 地址              | 名称     | 说明             | 默认值             | 读写  |
|:--------------- |:------ |:-------------- |:--------------- |:--- |
| `0x0100~0x0105` | MAC 地址 | 6 个寄存器，MAC 地址  | 出厂唯一            | R/W |
| `0x0106~0x0107` | IP 地址  | 2 个寄存器，IPv4 地址 | `192.168.1.12` | R/W |
| `0x0108~0x0109` | 子网掩码   | 2 个寄存器，子网掩码    | `255.255.255.0` | R/W |
| `0x010A~0x010B` | 默认网关   | 2 个寄存器，默认网关    | `192.168.1.1`   | R/W |

#### 3.6.1 IP 地址配置 (0x0106)

读取或修改传感器 IPv4 地址。以 uint16 数组形式存储，每 2 字节对应一个 IP 段。

**读 IP 地址：**

```
请求: 00 10 00 00 00 06 01 03 01 06 00 02
响应: 00 10 00 00 00 07 01 03 04 C0 A8 01 C8
      → 192.168.1.200
```

**改 IP 为 192.168.1.100：**

```
请求: 00 11 00 00 00 09 01 10 01 06 00 02 04 C0 A8 01 64
响应: 00 11 00 00 00 06 01 10 01 06 00 02
```

> 修改后需重启传感器生效。

## 5 常见问题 (FAQ)

**Q: 写触发指令时，上次写入的值就是 0x0001，再写 0x0001 还有效吗？**

A: 有效。传感器检测的是 Modbus 写操作事件（功能码 0x06），而不是寄存器值的变化。每次写操作都会触发对应动作，触发后寄存器值自动归零。上位机每次固定写入 0x0001 即可。

**Q: 通信超时后重发指令会导致重复触发吗？**

A: 会。传感器无法区分"新指令"和"超时重发"，每次收到写事件都会执行。建议在应用层通过事务 ID 去重，或在确认前一次已生效后再发下一条。

**Q: 标定矩阵如何更新？**

A: 标定矩阵（解耦矩阵）的读写由厂家通过 **RS-485 通道**完成，不在 Modbus-TCP 协议中体现。

**Q: 如何"取消去皮"（恢复绝对零点）？**

A: 写 `0x0031` 触发取消清零，传感器自动将 0x0050~0x005B 全部置零，此时 `F_zero[i] = 0`，输出值 = 原始采集值。

**Q: kg 和 N 格式有什么区别？如何切换？**

A: kg 和 N 均为矩阵解耦滤波后的六维力数据（已扣除零点偏移），仅单位不同。两者共用同一组数据寄存器 `0x0033~0x003E`，通过写 `0x0032` 切换：写 `1` → kg 格式，写 `2` → N 格式（默认）。转换关系：`kg 值 = N 值 ÷ 9.80665`。

**Q: 过载阈值设置了，传感器会触发硬件保护吗？**

A: 不会。过载阈值仅用于软件告警（系统状态寄存器 bit3），不触发硬件保护。

**Q: 网络参数修改后什么时候生效？**

A: 网络参数（IP、子网掩码、网关、MAC）修改后需重启传感器才能生效。

**Q: TCP 连接断开后数据发送会停止吗？**

A: 不会自动停止。传感器作为 TCP Server 持续发送数据，不受单个客户端断开影响。如需停止发送，请写 0x0001 寄存器。

**Q: 多个客户端同时连接可以吗？**

A: 支持。传感器作为 Modbus TCP Server 支持多客户端并发连接，每个客户端独立获取数据。
