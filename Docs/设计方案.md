# 六维力传感器 Modbus-TCP/RS485 通讯模块 — 设计方案

> 版本：v1.3 | 日期：2026年7月 | MCU：STM32F103CBT6 | ⚠ v1.3 修正 W5500 初始化流程（BS 编码、Buffer 分配、寄存器顺序）

## 1 系统概述

### 1.1 系统功能

本模块基于 STM32F103CBT6 + W5500 + LHA7668B + MAX13487 硬件平台，实现：

- **六维力传感器数据采集**：通过 LHA7668B 24位Σ-Δ ADC 采集6路差分信号
- **Modbus-TCP 通信**：通过 W5500 以太网芯片，作为 TCP Server 在端口 502 提供 Modbus-TCP 服务
- **RS485 本地配置**：通过 MAX13487 485 收发器，实现对传感器的参数配置（矩阵上传、格式切换、Debug等）
- **数据输出**：支持 500Hz / 1000Hz 数据发送频率，输出 N/kg/mV 三种格式

### 1.2 硬件接口总览

```
                     STM32F103CBT6
                    ┌──────────────┐
    LHA7668B (ADC)  │              │  W5500 (Ethernet)
    ─────────────── │              │ ───────────────
    PB12 ─── CS# ───│ SPI2         │── PA4 (CS) ──── SCSn
    PB13 ─── SCLK ──│              │── PA5 (SCK) ─── SCLK
    PB14 ─── DOUT ──│              │── PA6 (MISO) ── MISO
    PB15 ─── DIN ───│              │── PA7 (MOSI) ── MOSI
                    │              │── PB10 ──────── INTn (W5500中断)
    MAX13487 (485)  │              │── PB11 ──────── RSTn (W5500复位)
    ─────────────── │              │
    PA2 ─── TX ─────│ USART2       │
    PA3 ─── RX ─────│              │
                    └──────────────┘
```

### 1.3 关键性能指标

| 指标 | 目标值 | 备注 |
|:---|:---|:---|
| ADC 每通道速率 | ~1090 Hz（1000Hz模式）/ ~648 Hz（500Hz模式） | 全功耗，sinc4序列器6ch扫描 dead=30（手册第48页） |
| 数据输出频率 | 500Hz / 1000Hz 可选 | 由TIM2定时触发 |
| Modbus-TCP 响应 | < 5ms | 控制指令 |
| RS485 波特率 | 460800 bps（默认） | 可配置 691200/921600 |
| TCP 连接数 | 最大4个并发客户端 | W5500 Socket 0~3 |

## 2 系统时钟配置

### 2.1 时钟树设计

STM32F103CBT6 最高主频 72MHz，使用外部 8MHz HSE 晶振，经 PLL 倍频至 72MHz。

```
HSE (8MHz) ─→ PLL (×9) ─→ SYSCLK = 72MHz
                            ├── AHB = 72MHz
                            ├── APB1 = 36MHz (÷2)
                            │   ├── TIM2~TIM4 时钟 = 72MHz (APB1×2, 因预分频≠1)
                            │   ├── SPI2 时钟 = 36MHz
                            │   └── USART2 时钟 = 36MHz
                            └── APB2 = 72MHz (÷1)
                                └── SPI1 时钟 = 72MHz
```

**为什么这样配置：**

| 配置项 | 值 | 原因 |
|:---|:---|:---|
| SYSCLK | 72MHz | 最大主频，确保足够算力处理 1kHz 数据流和 TCP 协议栈 |
| APB1 | 36MHz (÷2) | STM32F103 最大 APB1 = 36MHz，使得定时器时钟 = 72MHz |
| APB2 | 72MHz (÷1) | SPI1 挂在 APB2，给 W5500 提供高速 SPI |
| TIM2 时钟 | 72MHz | APB1 预分频≠1，定时器时钟 = 2×APB1 = 72MHz |
| USART2 时钟 | 36MHz | 高精度波特率生成，36MHz / 460800 ≈ 78.125 → 支持 460800 波特率 |

### 2.2 hs.ioc 修改要点

在 STM32CubeMX 中需修改的配置项：

| 配置项 | 当前值 | 目标值 | 说明 |
|:---|:---|:---|:---|
| RCC → HSE | 外部晶振 | 外部晶振 | 不变 |
| RCC → PLL Source | — | HSE | 选择 HSE 作为 PLL 输入 |
| RCC → PLL Mul | — | ×9 | 8MHz × 9 = 72MHz |
| RCC → SYSCLK Source | — | PLLCLK | 选择 PLL 输出 |
| RCC → APB1 Prescaler | — | ÷2 | 36MHz（定时器时钟=72MHz） |
| SPI1 BaudRate | 2 MBits/s | 9 MBits/s | 72/8 = 9MHz（W5500 最大支持约 33MHz） |
| SPI2 BaudRate | 4 MBits/s | 4.5 MBits/s | 36/8 = 4.5MHz（LHA7668B SPI 上限约 5MHz） |
| USART2 BaudRate | 115200 | 460800 | RS485 默认波特率 |
| TIM2 Prescaler | 72-1 | 72-1 | 72MHz / 72 = **1MHz** 计数频率 |
| TIM2 Period | 1000-1 | **1000-1** (1kHz) / **2000-1** (500Hz) | 软件中动态切换 |

> TIM2 计数频率 1MHz → 1000 个计数值 = 1ms → 正好 1000Hz 定时精度。

## 3 LHA7668B ADC 配置

### 3.1 ADC 工作原理

LHA7668B 是 24 位 Σ-Δ ADC，内置 PGA（增益 1~128）、多路复用器和通道序列器。支持 8 路差分输入，可通过通道序列器自动轮流采样已使能通道。

**关键概念：**

- **主时钟 fCLK**：全功耗=614.4kHz，中功耗=153.6kHz，低功耗=76.8kHz
- **FS 寄存器**：决定数据速率。标准模式单通道 ODR = fCLK / (32 × FS)（FS≥1），fCLK/16（FS=0）
- **连续转换 + 通道序列器**：设置 CONVERSION=1 并使能多通道后，ADC 自动进入零延迟模式 + 序列器，逐个通道循环扫描。SINGLE_CYCLE 位无影响。
- **零延迟模式建立时间**：t_settle = (4 × 32 × FS + DeadTime) / fCLK（FS≥1），(4 × 16 + DeadTime) / fCLK（FS=0）

> **DeadTime 区分（手册第 47-48 页）**：
> - 手动切换通道（写寄存器）：DeadTime = 60（FS=1）/ 94（FS>1）
> - **通道序列器（自动扫描）**：**第 48 页明确死区时间减至 30**
> 
> **⚠ v1.2 关键纠正**：v1.1 用了手动切通道的 94/60，实际序列器 dead 仅 30，建立时间明显更短。

### 3.2 功耗模式选择

| 模式 | fMOD | 最大 ODR（FS=1） | 典型功耗 (LHA7668B) |
|:---|:---|:---|:---|
| 低功耗 | fCLK/32 = 153.6 kHz | 4800 SPS | 183 µA |
| 中功耗 | fCLK/16 = 307.2 kHz | 9600 SPS | 260 µA |
| **全功耗** | **fCLK/4 = 1.2288 MHz** | **38400 SPS** | **750 µA** |

> 内部主时钟 fCLK = 4.9152 MHz（典型值）

### 3.3 通道序列器真实采样率分析（⚠ v1.1 重大修正）

#### 3.3.1 核心公式

LHA7668 通道序列器使用 sinc4 零延迟模式（序列器自动触发，SINGLE_CYCLE 位无影响）。

> **⚠ 重要：多通道强制进入零延迟模式。** 手册第 51 页明确："使能多个通道时，ADC 会自动进入零延迟模式"。即只要选了 ≥2 个通道，以下"标准模式"公式就不再适用。

**标准模式单通道 ODR**（仅 1 通道使能时有效，6 通道下已不适用）：
```
f_ADC = f_CLK / (32 × FS[10:0])           (FS ≥ 1, 仅单通道)
f_ADC = f_CLK / 16                          (FS = 0, 仅单通道, =38400 SPS)
```

**零延迟模式单通道 ODR**（手册第 47 页，接近序列器实际）：
```
f_ADC = f_CLK / (4 × 32 × FS[10:0])       (FS ≥ 1)
f_ADC = f_CLK / (4 × 16)                  (FS = 0, =9600 SPS)
```

**通道序列器下每通道建立时间**（手册第 47-48 页）：
```
t_settle = (4 × 32 × FS[10:0] + DeadTime) / f_CLK    (FS ≥ 1)
t_settle = (4 × 16 + DeadTime) / f_CLK                (FS = 0)
```

| 参数 | 含义 | 值 | 出处 |
|:---|:---|:---|:---|
| fCLK | 全功耗主时钟 | 614.4 kHz | 手册第 47 页 |
| DeadTime（手动切换）| 写寄存器切换通道 | 60（FS=1）/ 94（FS>1）| 手册第 47 页 |
| **DeadTime（序列器)** | **序列器自动切换** | **30** | **手册第 48 页明确说明** |

**6 通道扫描周期 & 每通道速率：**
```
T_scan = 6 × t_settle
f_per_ch = 1 / T_scan
```

> 手册第 48 页序列器说明：
> "使能多个通道时，器件会自动使用片内序列器，自动按顺序转换所有使能的通道。这种情况下，第一个转换需要表57所列出的完整建立时间。**对于随后的所有转换，各转换所需的时间同样等于建立时间，但死区时间减至30。**"

#### 3.3.2 FS 配置与每通道速率（全功耗、sinc4、序列器 dead=30）

| FS | 名义单通道 SPS | 零延迟 SPS | t_settle (dead=30) | 6ch 扫描 | **每通道速率** | ≥1000Hz | ≥500Hz |
|:---|:---|:---|:---|:---|:---|:---|:---|
| **0** | 38400 | 9600 | 153 μs = (64+30)/fCLK | **0.92 ms** | **~1090 Hz** | ✅ | ✅ |
| 1 | 19200 | 4800 | 257 μs = (128+30)/fCLK | **1.54 ms** | **~648 Hz** | ❌ | ✅ |
| 2 | 9600 | 2400 | 465 μs = (256+30)/fCLK | **2.79 ms** | **~358 Hz** | ❌ | ❌ |
| 4 | 4800 | 1200 | 899 μs = (512+30)/fCLK | **5.39 ms** | **~185 Hz** | ❌ | ❌ |

> **纠正说明**：
> - "名义单通道 SPS" = 标准模式 ODR（fCLK/(32×FS)），仅在仅使能 1 个通道时有效；6 通道强制零延迟，此列无实用意义
> - "零延迟 SPS" = 零延迟单通道 ODR = fCLK/(128×FS)，6 通道序列器实际更接近这列
> - 序列器每通道速率 = fCLK / [6×(128×FS + 30)]，**dead=30 来自手册第 48 页**
> - 原方案错误地认为 FS=6 可达 1066 Hz —— FS>0 速率急剧下降

#### 3.3.3 1000Hz 输出模式配置

**结论：FS=0 满足 6 通道 1000Hz（每通道 ~1090 Hz），这是 ADC 硬件的物理极限。**

| 参数 | 值 | 说明 |
|:---|:---|:---|
| 功耗模式 | **全功耗** | 必须用最高时钟，无替代方案 |
| 滤波器类型 | sinc4 | 零延迟模式（序列器自动启用） |
| FS[10:0] | **0** (0x000) | 最大速度 |
| 通道数 | 6 | 六路差分 |
| 每通道速率 | **~1090 Hz** | 序列器 dead=30，公式 t=(64+30)/fCLK×6 |
| 增益 | 128 | 匹配微弱力传感器信号 |
| RMS 噪声 (增益=128) | ~2.5 µV | 高速下噪声最高（参考手册表 9） |

> **速度瓶颈说明：**
> - 38400 SPS 是**标准模式、仅 1 个通道使能**时的速率，6 通道下不存在
> - 6 通道自动强制零延迟 + 序列器，每通道 t = (64+30)/fCLK ≈ 153μs，扫描 ≈ 0.92ms
> - **每通道 ~1090 Hz 是 LHA7668 + 6ch 序列器的物理上限**
> - FS=1 降到 ~648 Hz（不够 1000Hz）；减少通道数或用多片 ADC 可提速

#### 3.3.4 500Hz 输出模式配置

500Hz 模式余量充裕，推荐 FS=1：

| 参数 | 方案 A（推荐） | 方案 B |
|:---|:---|:---|
| FS[10:0] | **1** (0x001) | 0 (0x000) |
| 每通道速率 | **~648 Hz** | ~1090 Hz |
| 速率余量 | +148 Hz (30%) | +590 Hz (118%) |
| RMS 噪声 (增益=128) | **~1.2 µV** | ~2.5 µV |
| 优势 | **噪声减半** | 速度余量大 |

**推荐方案 A（FS=1）**：648 Hz 远超 500 Hz 需求，噪声仅 FS=0 的一半。FS=2 降至 ~358 Hz 不满足需求。

### 3.5 通道配置

6 路差分信号映射到 LHA7668B 的 8 个差分输入通道中：

| LHA7668 通道 | 差分输入 | 传感器轴 | 增益 | 配置编号 (Setup) |
|:---|:---|:---|:---|:---|
| AIN0-AIN1 | CH0 | Fx | 128 | Setup 0 |
| AIN2-AIN3 | CH1 | Fy | 128 | Setup 0 |
| AIN4-AIN5 | CH2 | Fz | 128 | Setup 0 |
| AIN6-AIN7 | CH3 | Mx | 128 | Setup 0 |
| AIN8-AIN9 | CH4 | My | 128 | Setup 0 |
| AIN10-AIN11 | CH5 | Mz | 128 | Setup 0 |

> 所有 6 通道使用 Setup 0（增益 128、sinc4、全功耗），FS 按模式设为 0（1000Hz）或 1（500Hz）。

### 3.6 ADC 寄存器配置流程

``` 
上电 → 复位 ADC → 配置 ADC 控制寄存器（全功耗模式、内部时钟）
    → 配置通道寄存器（使能 CH0~CH5，绑定 Setup 0）
    → 配置 Setup 0（增益=128，sinc4 滤波器）
    → 配置滤波器寄存器 0（FS=0 用于 1000Hz / FS=1 用于 500Hz，sinc4）
    → 使能连续转换模式 + 通道序列器
    → 等待 /RDY 信号读取数据
```

> **注意**：使能多通道后 ADC 自动进入零延迟模式，**无需**设置 SINGLE_CYCLE 位。序列器按 CH0→CH1→...→CH5 自动循环扫描。

## 4 定时器配置

### 4.1 TIM2 — 数据发送定时器

TIM2 用作数据发送的精确时基。

| 参数 | 值 | 说明 |
|:---|:---|:---|
| 时钟源 | 内部时钟 (72MHz) | APB1=36MHz, TIM CLK=72MHz |
| 预分频器 (PSC) | 72-1 = 71 | 72MHz / 72 = 1MHz |
| 自动重装载 (ARR) | **1000-1** (1kHz) / **2000-1** (500Hz) | 软件中根据模式切换 |
| 中断 | TIM2_IRQn，优先级 1 | 高于 SysTick(15)，低于其他 |

**中断触发频率：**
- 1kHz 模式：ARR = 999, 触发频率 = 1MHz / (999+1) = **1000 Hz**
- 500Hz 模式：ARR = 1999, 触发频率 = 1MHz / (1999+1) = **500 Hz**

**TIM2 ISR 中做什么：**
1. 检查 ADC 数据就绪标志
2. 如果数据就绪，读取 6 通道最新数据并存入发送缓冲区
3. 触发 TCP 数据发送（设置发送标志，不在 ISR 中直接发送）
4. 如果连续发送模式使能，更新发送缓冲区

### 4.2 SysTick — 系统节拍

STM32 HAL 库默认 SysTick 1ms，用于：
- HAL_Delay() 延时
- W5500 轮询（如不用中断模式）
- Modbus-TCP 超时管理
- 软件看门狗喂狗

## 5 W5500 TCP/IP 通信

### 5.1 W5500 简介

W5500 是硬件 TCP/IP 协议栈芯片，内置 10/100M 以太网 PHY 和 MAC，通过 SPI 与 MCU 通信。

| 特性 | 配置 |
|:---|:---|
| SPI 接口 | SPI1, Mode 0, 最高 9MHz |
| 中断引脚 | PB10 (W5500_INT), 下降沿触发 |
| 复位引脚 | PB11 (W5500_RST), 低电平复位 |
| CS 引脚 | PA4, 软件控制 |
| Socket 数量 | 8 个，使用 Socket 0~3 作为 TCP Server（最多 4 并发） |
| 监听端口 | 502 (Modbus-TCP 标准端口) |

#### 5.1.1 SPI 帧格式（VDM 模式）

W5500 采用 **可变数据长度模式（VDM）**，每帧 3 个阶段：

```
第一阶段：16 位 地址段
   ┌──────┬──────┬─────────────────────────────────┐
   │ BIT15│BIT14 │ BIT13~BIT8    BIT7~BIT0         │
   │ R/W  │  O   │ [BS4:BS0,00] [OFS7:OFS0]       │
   │  0=读│ MODE │ 块选择+保留    偏移地址           │
   │  1=写│  0=VDM│                                 │
   └──────┴──────┴─────────────────────────────────┘

第二阶段：8 位 控制段（可选，仅写操作时）
   控制段仅在写操作且 O MODE=0 (VDM) 时发送。

第三阶段：N 字节 数据段
   读操作：W5500 → MCU (N 字节)
   写操作：MCU → W5500 (N 字节)
```

#### 5.1.2 BS[4:0] 块选择位编码（关键！）

BS[4:0] 是 **交错排列** 的 5 位区域选择码，**不是分组排列**：

```
BS[4:0] = 0x00 → Common Register 区 (通用寄存器)
BS[4:0] = 0x01 → Socket 0 Register 区
BS[4:0] = 0x02 → Socket 0 TX Buffer 区
BS[4:0] = 0x03 → Socket 0 RX Buffer 区
BS[4:0] = 0x04 → Socket 1 Register 区
BS[4:0] = 0x05 → Socket 1 TX Buffer 区
BS[4:0] = 0x06 → Socket 1 RX Buffer 区
...
```

**通用公式**：Socket n (n = 0~7)：

| 区域 | BS[4:0] 编码 |
|:---|:---|
| Socket n Register | `1 + 4*n` |
| Socket n TX Buffer | `2 + 4*n` |
| Socket n RX Buffer | `3 + 4*n` |

> **⚠ 易错点**：TX/RX Buffer 的 BS 值 = `2+4n` 和 `3+4n`，**不是** `0x10+n` 和 `0x18+n`。写成 `0x10`/`0x18` 会导致访问错误的内存块（分别指向 Socket 4/6 的寄存器区），Socket OPEN 将失败且 `Sn_SR` 读回垃圾值。

### 5.2 网络参数

| 参数 | 默认值 | 存储位置 |
|:---|:---|:---|
| MAC 地址 | 出厂唯一 | EEPROM/Flash |
| IP 地址 | 192.168.1.12 | EEPROM/Flash (可通过 Modbus 寄存器 0x0106 修改) |
| 子网掩码 | 255.255.255.0 | EEPROM/Flash |
| 网关 | 192.168.1.1 | EEPROM/Flash |

### 5.3 W5500 Socket 分配

| Socket | 用途 | RX Buffer | TX Buffer | 模式 |
|:---|:---|:---|:---|:---|
| Socket 0 | Modbus-TCP Server (主) | 2 KB | 2 KB | TCP Server, 端口 502 |
| Socket 1 | Modbus-TCP Server (备用) | 2 KB | 2 KB | TCP Server, 端口 502 |
| Socket 2 | Modbus-TCP Server (备用) | 2 KB | 2 KB | TCP Server, 端口 502 |
| Socket 3 | Modbus-TCP Server (备用) | 2 KB | 2 KB | TCP Server, 端口 502 |
| Socket 4~7 | 保留（禁用） | 0 KB | 0 KB | — |

> **⚠ 关键**：W5500 内存分配是批量触发的——必须向**全部 8 个 Socket** 写入 `Sn_RXBUF_SIZE` 和 `Sn_TXBUF_SIZE` 后，硬件才一次性完成分配。因此即使 Socket 4~7 不使用，也必须将其缓冲区大小写为 0。**在全部 8 个 Socket 完成分配之前，任何 OPEN 命令都不会生效。**
>
> W5500 自动处理 TCP 握手、重传、ACK 等，MCU 只需读写 Socket 寄存器即可收发数据。

### 5.4 W5500 初始化流程（⚠ v1.3 修正）

W5500 的初始化顺序**非常关键**，顺序错误会导致 Socket OPEN 失败或状态异常。

```
1. w5500_hw_reset()          ← 硬件复位（拉低 RSTn ≥ 500μs）
2. w5500_read_version()      ← 验证 SPI 通信 & 芯片版本 (应为 0x04)
3. w5500_set_mac()           ← 设置 MAC 地址（Common Register 区）
4. w5500_set_ip()            ← 设置 IP 地址
5. w5500_set_gateway()       ← 设置网关
6. w5500_set_subnet()        ← 设置子网掩码
7. w5500_configure_buffers() ← ★ 批量分配全部 8 个 Socket 缓冲区 ★
8. 等待 PHY Link UP          ← 轮询 PHYCFGR.LNK 位，超时 3s
9. w5500_socket_init(0)      ← 每个 Socket: Sn_MR → Sn_PORT → Sn_KPALVTR → Sn_CR=OPEN
10. w5500_socket_listen(0)    ← Sn_CR=LISTEN，等待 TCP 连接
```

**各步骤要点说明：**

| 步骤 | 关键注意事项 |
|:---|:---|
| 7. Buffer 配置 | **必须一次写完 8 个 Socket**，否则内存不分配，OPEN 必然失败。Socket 0~3 各 2KB，Socket 4~7 写 0 |
| 9. Socket Init | 寄存器写入顺序：`Sn_MR` → `Sn_PORT` → `Sn_KPALVTR` → `Sn_CR=OPEN`。**`Sn_KPALVTR` 必须在 OPEN 之前** |
| 9. 等待 OPEN 完成 | `Sn_CR=OPEN` 后需 `HAL_Delay(2)` 等待命令生效，再轮询 `Sn_SR`。若立即读取可能读到旧状态 |
| 9. 轮询 Sn_SR | 最多等待 100ms，预期值为 `SOCK_INIT (0x13)`。若返回非 0x00~0x17 值，说明地址映射有误 |

> **⚠ 本次开发中踩过的坑**：详见 `Docs/w5500-debug-notes.md`（BS 编码错误 + Buffer 未批量分配 + KPALVTR 写在 OPEN 之后）。

### 5.5 W5500 驱动架构

采用**中断 + 轮询混合模式**，支持最多 4 个 TCP Client 同时连接（Socket 0~3，均监听端口 502）。

#### 5.5.1 架构概览

```
W5500 INT (PB10 下降沿)
    │
    ▼
中断中仅置标志位，不读写 W5500（SPI 不可重入）
    │
    ▼
主循环轮询
    ├── 读取 W5500 全局 IR 寄存器 → 被触发的 Socket 位
    ├── 遍历 Socket 0~3：
    │   ├── Sn_IR 检查事件（CON / DISCON / RECV / TIMEOUT）
    │   ├── 根据 Sn_SR 状态机切换
    │   └── RECV 事件 → 读取数据 → Modbus 处理 → SEND 响应
    └── 空闲 Socket 自动恢复 LISTEN 状态
```

#### 5.5.2 每 Socket 连接状态机

```
 CLOSED ──[OPEN]──► INIT ──[LISTEN]──► LISTEN
    ▲                                      │
    │                              [SYN 到达, Sn_IR=CON]
    │                                      │
    │                                      ▼
    │                              ESTABLISHED ◄──► 数据收发
    │                                      │
    │                    [对端关闭 / 超时]  │
    │                                      ▼
    └──────────────────────────────── CLOSE_WAIT
```

**前置条件：** 在 OPEN 之前必须完成：
1. `Sn_RXBUF_SIZE` / `Sn_TXBUF_SIZE` 已配置（参见 5.4 初始化流程步骤 7）
2. `Sn_KPALVTR` 已在 OPEN 之前写入（TCP Keep-Alive 定时器）

#### 5.5.3 中断处理策略

- **PB10 外部中断**：W5500 任一 Socket 产生事件时拉低 INT 脚
- 中断服务函数中**仅置 `w5500_irq_pending = 1` 标志**，不操作 SPI
- 原因：SPI 为阻塞式 HAL 接口，不可在中断上下文中被另一个 SPI 操作抢占
- 主循环检测标志后执行实际事件处理

#### 5.5.4 多客户端并发处理

W5500 各 Socket 的 TX/RX 缓冲区相互独立（每个 2KB），硬件级 TCP 状态机独立运行：

| 步骤 | 操作 |
|:---|:---|
| 缓冲区分配 | **先调用 `w5500_configure_buffers()` 批量分配 8 个 Socket** |
| 初始化 | Socket 0~3 全部 OPEN → LISTEN，绑定端口 502 |
| 新连接 | W5500 硬件自动完成三次握手，Sn_IR.CON 置位 |
| 数据到达 | Sn_IR.RECV 置位 → 主循环读取 Sn_RX_RSR → 调用 w5500_socket_recv() |
| 断开 | Sn_IR.DISCON 置位 → 主循环 CLOSE → 重新 OPEN → LISTEN |
| 超时 | Sn_IR.TIMEOUT → CLOSE → 重新 OPEN → LISTEN

## 6 RS485 通信

### 6.1 硬件配置

| 参数 | 配置 |
|:---|:---|
| UART 外设 | USART2 |
| TX/RX 引脚 | PA2 / PA3 |
| 波特率 | 460800 bps (默认) |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 485 方向控制 | 需额外 GPIO 控制 MAX13487 的 DE//RE 引脚 |
| 接收方式 | UART 空闲中断 + DMA |

> **注意**：MAX13487 是自动方向控制的 485 芯片（内置方向切换），但确认是否需要 MCU 控制 RE/DE 引脚。如果是标准 MAX13487，需要 MCU 控制收发方向；如果是 MAX13487EESA+（带自动方向），则不需要。根据硬件设计确认。

### 6.2 USART2 中断配置

| 中断 | 优先级 | 用途 |
|:---|:---|:---|
| USART2_IRQn | 0 (最高) | 接收数据、IDLE 中断检测帧结束 |
| USART2 DMA RX | — | DMA 循环接收，减少 MCU 开销 |

### 6.3 RS485 帧解析

```
帧格式: AA 55 [CMD] [DATA...N] 0D 0A
         |  固定帧头  | 可变数据域 | 固定帧尾 |
```

解析流程：
1. 环形缓冲区累积接收数据
2. IDLE 中断或定时检测触发帧解析
3. 搜索帧头 `AA 55`，提取命令码
4. 搜索帧尾 `0D 0A`，确定数据长度
5. 查表执行对应命令处理函数

### 8.2 主循环流程

```
while(1)
{
    // 1. W5500 TCP 事件处理 (优先级最高)
    w5500_process_events();
    //   ├── 检测 Socket 连接/断开事件
    //   ├── 读取接收缓冲区 → 解析 Modbus-TCP 帧
    //   ├── 执行寄存器操作 (读/写/触发)
    //   └── 发送响应帧

    // 2. RS485 帧处理
    rs485_process_rx();
    //   ├── 从环形缓冲区提取完整帧
    //   ├── 解析命令码
    //   └── 执行对应命令 (矩阵上传/格式切换/Debug等)

    // 3. ADC 数据处理 & TCP 数据发送
    if (g_send_mode == SEND_MODE_CONTINUOUS && g_data_ready) {
        g_data_ready = 0;
        sensor_process_data();     // 矩阵解耦 + 零点校正
        modbus_tcp_send_data();    // 构造 TCP 数据帧并发送
    }

    // 4. 单次转换处理 (仅在单次模式)
    if (g_send_mode == SEND_MODE_SINGLE && g_single_trig) {
        g_single_trig = 0;
        sensor_process_data();
        // 数据存入 Modbus 寄存器 0x0033~0x003E，等待上位机读取
    }

    // 5. LED 状态指示
    led_update();  // 心跳、连接状态、错误指示
}
```

### 8.3 中断服务流程

#### TIM2 中断 (1kHz / 500Hz)

```
TIM2_IRQHandler()
{
    HAL_TIM_IRQHandler(&htim2);

    if (发送模式 == 固定频率发送) {
        // 1. 检查 ADC 是否有新数据（查询 /RDY 或状态寄存器）
        if (adc_data_ready()) {
            // 2. 通过 SPI2 连续读取 6 通道 × 3 字节 = 18 字节数据
            adc_read_6channels(raw_data);

            g_data_ready = 1;

            // ADC 数据还没准备好，记录溢出计数
            g_overflow_cnt++;
        }
    }

    __HAL_TIM_CLEAR_IT(&htim2, TIM_IT_UPDATE);
}
```

## 9 关键时序分析

### 9.1 1000Hz 模式时序

```
时间轴 (1ms周期, TIM2触发)
│
│← ─ ─ ─ ─ ─ 1ms 周期 (1000Hz) ─ ─ ─ ─ ─ →│
│
├─[T0]──[T1]──────────────────────────[T2]──┤
│  TIM2   数据读取+处理+TCP发送  完成等待    │
│  中断                                  TIM2
│                                        中断
│
T0: TIM2 中断触发
T1: ADC 6通道数据读取完成 (SPI2 @4.5MHz, 18字节≈32μs)
    ⚠ ADC 序列器扫描≈0.92ms < TIM2 1ms，时序余量 ~80μs，数据及时刷新
    矩阵运算 (6×6 float, ≈20μs @72MHz)
    TCP 帧构造 (≈5μs)
    SPI1 发送 34字节 (W5500 @9MHz, ≈30μs)
T2: 下次 TIM2 中断

总处理时间 ≈ 32+20+5+30 = 87μs << 1ms ✓
CPU 占用率 ≈ 8.7%
```

### 9.2 ADC 与 TIM2 时序配合（1000Hz 模式，FS=0）

```
ADC 序列器扫描（FS=0, dead=30, 每通道 t_settle≈153μs, 6通道扫描≈0.92ms）

通道:  CH0    CH1    CH2    CH3    CH4    CH5
      [Fx]   [Fy]   [Fz]   [Mx]   [My]   [Mz]
      ~153μs ~153μs ~153μs ~153μs ~153μs ~153μs
│                                              │
└────────── 1轮扫描 ≈ 0.92 ms ─────────────────┘
                                                    │
                                              TIM2 中断 (每1ms)
                                              读取最新一轮数据

✅ 时序满足：ADC 0.92ms < TIM2 1ms，余量 ~80μs。每次 TIM2 中断时已有完整新数据，不会读到部分更新。
```

### 9.3 500Hz 模式时序（FS=1）

```
ADC 序列器扫描（FS=1, dead=30, t_settle≈257μs, 6通道扫描≈1.54ms）

1轮扫描 ≈ 1.54 ms
TIM2 中断每 2ms（500Hz）

余量 = 2000 - 1543 = 457 μs（非常充裕）
CPU 占用率更低，噪声性能更好（RMS 噪声 ~1.2μV vs FS=0 的 ~2.5μV）
```

### 9.4 数据通过率验证

| 模式 | FS | t_settle/通道 (dead=30) | 6通道扫描 | 每通道速率 | TIM2周期 | 余量 |
|:---|:---|:---|:---|:---|:---|:---|
| 1000Hz | 0 | ~153 μs | ~0.92 ms | **~1090 Hz** | 1.00 ms | **+80 μs** ✅ |
| 500Hz | 1 | ~257 μs | ~1.54 ms | **~648 Hz** | 2.00 ms | **+457 μs** ✅ |

> **✅ v1.2 结论**：dead=30 后时序充裕。1000Hz 模式有 ~80μs 余量，不再紧张。建议 Phase 1 用逻辑分析仪实测 /RDY 周期确认。

## 10 存储设计

### 10.1 参数存储方案

使用 STM32F103CBT6 内部 Flash（128KB）的最后 2 页（1KB/页）作为参数存储区：

| 偏移 | 大小 | 内容 | 说明 |
|:---|:---|:---|:---|
| 0x000 | 6 字节 | MAC 地址 | 出厂写入 |
| 0x008 | 4 字节 | IP 地址 | 默认 192.168.1.12 |
| 0x00C | 4 字节 | 子网掩码 | 默认 255.255.255.0 |
| 0x010 | 4 字节 | 网关 | 默认 192.168.1.1 |
| 0x014 | 144 字节 | 解耦矩阵 (6×6 float32) | 通过 RS485 0x22 命令上传 |
| 0x0A4 | 24 字节 | 零点偏移 (6×float32) | 通过清零命令自动保存 |
| 0x0BC | 16 字节 | 序列号 (SN) | 出厂写入 |
| 0x0CC | 2 字节 | 固件版本 | 编译时写入 |
| 0x0D0 | 4 字节 | CRC32 | 参数完整性校验 |

### 10.2 Flash 写入策略

- 上电时读取参数到 RAM，在 RAM 中修改
- 修改后调用 Flash 编程函数写入（注意关闭中断、使用 HAL_FLASH 库）
- 掉电不丢失，支持参数持久化

## 11 错误处理与诊断

### 11.1 错误类型与处理

| 错误类型 | 检测方式 | 处理 |
|:---|:---|:---|
| EEPROM/Flash 读取失败 | CRC32 校验不通过 | 加载默认参数，置 EEPROM_FAIL 标志 |
| ADC 初始化失败 | 读取 ADC ID 寄存器异常 | 置 ADC_FAIL 标志，停止采集 |
| W5500 版本读取失败 | 读 W5500 版本寄存器返回非 0x04 | 检查 SPI 接线、CS 引脚、供电 |
| W5500 Socket OPEN 失败 | `Sn_SR` 返回非合法值 (0x00~0x17 之外) 或不为 `SOCK_INIT` | 检查：① BS 编码是否正确 ② Buffer 是否已批量分配 ③ `Sn_KPALVTR` 是否在 OPEN 前写入 |
| TCP 通信异常 | Socket 超时/断开 | 自动重连，递增 comm_error_cnt |
| CRC 校验失败 | Modbus/RS485 帧校验 | 置 CRC_ERR 标志（读后自动清零） |
| 过载 | 任一通道 ≥ 阈值 | 置 OVERLOAD 标志 |
| 参数越界 | 写入值超出阈值范围 | 置 PARAM_ERR，拒绝写入 |
| ADC 数据溢出 | TIM2 中断时 ADC 无新数据 | 递增 overflow_cnt，发送上一帧数据 |

### 11.2 LED 状态指示

| LED | 状态 | 含义 |
|:---|:---|:---|
| 黄色 LINKLED | 常亮 | 以太网物理层已连接 |
| 黄色 LINKLED | 闪烁 | 以太网活动 |

## 14 字节序处理要点

这是最容易出错的环节，务必注意：

| 场景 | 字节序 | 示例 |
|:---|:---|:---|
| Modbus-TCP 寄存器 (uint16) | **大端** | `0x0001` = `[0x00, 0x01]` |
| Modbus-TCP 寄存器 (float32) | **小端** | 1.0 = `[0x00, 0x00, 0x80, 0x3F]` |
| RS485 数据帧 (float32) | **小端** | 1.0 = `[0x00, 0x00, 0x80, 0x3F]` |
| RS485 连续帧 (uint32 seq) | **小端** | 序列号 LE |
| LHA7668B ADC 输出 (24bit) | **大端** | 3 字节 MSB first |
| STM32 内存 (float) | **小端** (ARM) | 与 Modbus-TCP/RS485 float32 一致 |

**处理策略：**
- ADC 读取的 24 位数据在 MCU 内部统一转换为 float（ARM 小端格式）
- Modbus-TCP 输出 float 时直接使用（字节序一致）
- RS485 输出 float 时直接使用（`float_to_le()`，与 Modbus-TCP 一致）
- 解耦矩阵上传时 float 按小端接收（`le_to_float()`），存入前无需转换

```c
}
```
